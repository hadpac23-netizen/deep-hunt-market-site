# BOOM Durable Event Identity Skill

## Mission
Require database-level uniqueness before claiming browser/server dedup is durable.

## Required live proof
- canonical event_id generated by browser
- nullable analytics_events.event_id column
- UNIQUE(event_id)
- public/anonymous canonical event insertion blocked
- trusted server path writes event_id
- duplicate event_id is handled atomically by the database
- live function confirms the durable path is enabled

## Historical rule
Never invent or backfill canonical event IDs when the original identity was not persisted.
Historical rows remain NULL.

## Browser policy
Direct browser analytics may continue only as noncanonical rows.
Canonical event_id must travel through the trusted server path.

## Deployment order
1. owner-approved migration generated with Supabase CLI
2. apply schema/policy change
3. verify RLS/security and uniqueness
4. deploy compatible Edge Function
5. test duplicate event_id across independent requests
6. only then enable the durable identity flag
7. only then allow M23 durable_ready

## Safety
Do not treat local source, SQL proposals or metadata persistence as live durable dedup.
No deployment is authorized by this skill.
